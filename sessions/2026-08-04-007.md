## Milestone 8 implementation

- 8.1 adds `predict PROJECT --input FILE|- [--batch-size N]`, the strict
  `neural-c inputs 1` document, bounded in-memory batches, stable sample order,
  and staged all-or-nothing output. Positional prediction remains byte
  compatible for legacy projects.
- 8.2 adds `import-csv PROJECT CSV --schema FILE` with an explicit version 1
  schema, exact column ownership, quoted-field parsing, categorical mappings,
  locale-independent numbers, and source-row errors.
- 8.3 adds versioned `preprocessing.txt` metadata for `none`, `standardize`, and
  `minmax`. Statistics are fitted only on assigned training rows. Prediction
  deep-copies the metadata into its immutable snapshot and applies it before
  inference; imported validation/test datasets are already transformed.
- 8.4 adds deterministic SplitMix64 splitting with source-order output,
  per-class stratification for categorical labels, CSV/schema SHA-256
  provenance, and a rollback-capable, directory-synchronized multi-file
  transaction for train/validation/test/preprocessing files.
- 8.5 adds explicit `reject` and training-mean `mean` missing policies. Empty
  CSV inputs and exact `?` are missing; targets never permit missing values.
  Exact `?` also works in positional and document prediction only when the
  persisted policy allows it.
- Existing projects without `preprocessing.txt` retain identity input behavior
  and their exact legacy canonical dataset digest. Projects with preprocessing
  bind it and all import/split provenance into the dataset digest.
- Import refuses to invalidate existing weights or checkpoints and requires a
  non-empty validation split when project early stopping is enabled.
- Contracts and examples live in `docs/data-interfaces.md`; README,
  prediction, persistence, locking, specification, and roadmap documents were
  updated. Milestone 10.3 now explicitly retains backward loading rules for
  both checkpoint versions 1 and 2.
