## Configuration and compatibility

- `project.conf` accepts optional `shuffle 0|1`; absent or zero retains exact
  historical source order and canonical digest behavior.
- New projects always materialize the setting. `init --shuffle` selects one;
  the compile-time-overridable default remains zero.
- `inspect` reports `Shuffle: enabled|disabled`.
- Enabled shuffle appends `epoch_shuffle` and
  `splitmix64_fisher_yates_v1` to the canonical training stream. Changing it
  therefore invalidates incompatible weights/checkpoints before mutation.
- The canonical XOR training digest remains
  `08778dfaba9557e47d924f3010e4b972935e718b994c3a65eb2f0aac5de4ab6d`.

## Deterministic execution

- One opaque `NeuralSampleOrder` owns a `size_t[sample_count]` plan per training
  run and is regenerated in place for every executed absolute epoch.
- The epoch-local SplitMix64 seed uses the fixed domain
  `0x6e657572616c2d73`, the standard increment
  `0x9e3779b97f4a7c15`, the configured training seed, and the zero-based absolute
  epoch index.
- Descending Fisher-Yates uses rejection sampling with threshold
  `(0 - bound) % bound`, avoiding modulo bias with portable C11 arithmetic.
- Mini-batches slice logical positions. Workers receive source indices from the
  plan, while the coordinator reduces gradients in increasing logical order.
  Scheduling and worker count cannot change update arithmetic.
- The existing source-order executor API remains available; a new ordered API
  carries the explicit plan without exposing its storage.
- The data-import split shuffle is intentionally unchanged because its existing
  modulo traversal is persisted preprocessing behavior.

## Resume and persistence

- Fresh, resumed, and additional training all use absolute epoch identity. A
  resumed range beginning at `completed_epochs` regenerates that next epoch's
  plan directly.
- No mutable shuffle state or materialized permutation is persisted. Weights and
  checkpoint versions 1 and 2 remain unchanged.
- The model `rng_state` remains initialization provenance and is neither read
  nor modified by epoch shuffling.
- Completed-epoch checkpoints remain sufficient after hard failure, graceful
  interruption, refinement, and early-stopping paths.
