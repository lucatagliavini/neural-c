## Work Completed

- Implemented `predict <project> <INPUT ...>` for one or more samples. The
  positional input sequence is partitioned by the loaded model input width and
  rejects empty, partial, malformed, non-finite, or oversized requests.
- Added validated prediction snapshots. Loading holds the non-blocking shared
  project lock while parsing the complete project, computing canonical digests,
  constructing the runtime model, and transactionally loading `weights.txt`.
- Required prediction weights to match model, dataset, and training provenance
  and to contain at least the configured fresh-training epoch count.
- Released the project lock after snapshot validation. Inference then uses the
  immutable in-memory model, so later training cannot alter an in-flight
  prediction.
- Allowed prediction from stable baseline weights when a refinement checkpoint
  coexists. Versioned output reports `completed_epochs`, making the selected
  finalized snapshot explicit.
- Added deterministic parallel inference. Every pthread worker owns a model
  workspace and writes disjoint output slots; rows remain in input order and
  no cross-sample reduction occurs.
- Defined the version 1 output document in `docs/prediction.md`: magic/version,
  completed epochs, sample/input/output dimensions, indexed sample rows using
  `DBL_DECIMAL_DIG`, and a terminal `end` line. Worker counts are excluded so
  output remains byte-identical across execution settings.
- Added exact linear-model tests for sequential/parallel equivalence, effective
  worker capping, lock release before inference, writer contention, missing or
  incomplete weights, digest mismatches, and deterministic lowest-failing
  sample selection.
- Extended CLI integration with multi-sample XOR inference, identical 1-versus-
  4-thread output, malformed and partial inputs, prediction contention, and
  baseline prediction during interrupted refinement.
- Fixed a pre-existing test race: the signal helper no longer probes `flock`
  and accidentally contends with the child it observes. It now waits
  non-intrusively for the child's lock descriptor through Linux `/proc`.
- Updated README, locking, parallel-execution, specification, roadmap, and
  repository guidance for the completed prediction contract.

## Open Considerations

- Positional prediction inputs are intentionally a flat sequence. Callers must
  use `--` before negative values that could otherwise be parsed as options.
- Prediction currently loads `train.txt` because the finalized weights include
  the dataset digest in their provenance. This makes snapshot validation
  complete, at the cost of loading the training dataset for inference.
- The CLI currently buffers all input and output values in memory. This is
  appropriate for the positional interface; a future streaming/bulk inference
  format should introduce bounded batches rather than silently changing this
  version 1 contract.
- Runtime execution was validated natively on x86-64. The ppc64le result is a
  cross-build/ELF verification; actual ppc64le runtime testing remains
  Milestone 6 work.
