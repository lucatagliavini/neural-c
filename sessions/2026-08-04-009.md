## Loss contract and implementation

- `project.conf` now accepts `mse`, `binary_cross_entropy`, and
  `categorical_cross_entropy`; help and inspection use the canonical names.
- MSE accepts every supported output activation and finite targets.
- BCE requires sigmoid output and exact binary targets. It supports one or more
  independent sigmoid outputs and is normalized by output width.
- CCE requires at least two softmax outputs and exactly one-hot targets. It is
  a per-sample class loss and is not divided by output width.
- Initialization, project loading, digest computation, CSV import, training,
  evaluation datasets, executors, and gradient checking enforce the same
  activation/output/target contract before material work or persistence.
- CSV target rejection occurs before the import transaction changes managed
  datasets.

## Numerical behavior

- BCE loss is evaluated from logits with stable softplus terms and uses the
  fused pre-activation gradient `(sigmoid(z) - y) / output_count`.
- CCE loss uses stable log-sum-exp from logits and the fused softmax gradient
  `p - y`; the separate softmax Jacobian is skipped at the output layer.
- Coherent training, validation, early-stopping, gradient-check, and project
  evaluation loss use logits. The detached probability-only API validates the
  probability domain and bounds exact zero/one for finite diagnostics.
- Deterministic sample ordering, compensated dataset loss summation, parameter
  layout, gradient reduction, and coordinator-only updates are unchanged.
