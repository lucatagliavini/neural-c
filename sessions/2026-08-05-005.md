## Optimizers and schedules

- Optimizer abstraction version 1 preserves the established
  `gradient_descent` update exactly and adds deterministic Momentum and Adam.
- Mutable updates are transactional: invalid or non-finite candidates leave
  both model parameters and live optimizer state unchanged.
- Project configuration and `init` support Momentum and Adam hyperparameters,
  plus constant, step, exponential, and plateau learning-rate schedules.
- Schedule state changes at coherent epoch boundaries and is deterministic
  across worker counts.

## Convergence control

- Optional divergence thresholds fail training without publishing new final
  weights.
- Optional target loss and maximum no-improvement epochs end successfully with
  explicit `loss_target` and `no_improvement` completion reasons.
- Existing target-epoch and validation early-stopping reasons remain explicit.
- Schedule and convergence observation is transactional, including counter and
  non-finite-rate failures.

## Persistence and continuation

- Stateful checkpoint format version 3 persists optimizer timestep and buffers,
  Adam powers, current learning rate, schedule transition/plateau state, and
  convergence state.
- Version 1 gradient-descent and version 2 early-stopping checkpoints remain
  supported under explicit compatibility rules.
- Interrupted Momentum/Adam runs resume exactly; schedule and convergence
  transitions affect the same next epoch as uninterrupted execution.
- Successful convergence before the configured target writes weights format 2
  with its explicit completion reason.
