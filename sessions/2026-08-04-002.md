  reduction order, periodic checkpoint boundaries, and loss reporting remain

  same-epoch parameter mismatches. Invalid states remain untouched.
- Retained the exclusive project lock across baseline validation, training,
  checkpoint writes, final weights replacement, and cleanup. Additional
  training fails immediately on contention or when a checkpoint already
  requires `--resume`.
- Added deterministic continuous-versus-refined equivalence tests, repeated
  refinement, zero-interval behavior, invalid state coverage, controlled signal

## Open Considerations

- Periodic checkpoint boundaries use cumulative absolute epoch numbers. A
  short refinement that crosses no configured multiple writes no periodic
  checkpoint; the prior final weights remain safe, and graceful signals still
  force a checkpoint.
- Gradient descent currently has no optimizer buffers and training consumes no
  random values after model initialization. Refinement therefore resets run
  and RNG state deterministically. A future stochastic optimizer or sampler
  would require its continuation state to be made explicit in persistence.
- As with earlier checkpoints, a parent-directory `fsync` error after a rename
  or unlink is an ambiguous reported failure, but every visible persistence
  file remains structurally valid and recoverable under the documented state
  machine.
