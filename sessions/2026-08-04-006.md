## Persistence compatibility clarification

- Persistence version 2 is used only when early stopping is enabled with a
  positive patience. It atomically stores current/best checkpoint models and
  records observed, selected, and target epochs in finalized weights.
- Existing projects, version 1 weights, and version 1 checkpoints remain valid
  while early stopping stays disabled. Older project configurations may omit
  the new early-stopping fields; explicit zero values preserve the old digest.
- Adding validation or test data for `evaluate` does not require rebuilding a
  project or retraining.
- Enabling early stopping on an already trained project changes training
  provenance by including its settings and canonical validation dataset. Old
  finalized weights should be archived and the model retrained; the model,
  training dataset, and project directory do not need to be regenerated.
